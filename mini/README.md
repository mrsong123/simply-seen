# 素见好物微信小程序

本目录为uni-app微信小程序，不以一个首页中的条件分支模拟多页。16个页面在`src/pages.json`中注册，可独立进入、返回、刷新和分享。

## 启动与构建

生产交付优先使用仓库根目录的统一配置入口：按根`.env.example`与[配置清单](../docs/configuration.md)填写根`.env`并放好密钥文件，在仓库根运行`python scripts/manage.py check`及`python scripts/manage.py build`。构建器从同一份配置传入实际AppID、API与素材域名，不要求修改小程序源码或再维护另一份生产配置。Python命令名按本机安装使用`python`、`python3`或Windows的`py -3`。

以下是仅针对本目录的独立开发方式：

```bash
npm ci
cp .env.example .env.local
npm run typecheck
npm run test
npm run build:mp-weixin
```

微信开发者工具导入`dist/build/mp-weixin`。开发监听使用`npm run dev:mp-weixin`。

`.env.local`需填写真实`WX_APP_ID`、`VITE_API_BASE_URL`和`VITE_ASSET_BASE_URL`。API地址包含`/api/v1`；素材地址提供`/art/*.png`。生产必须使用已配置为微信合法域名的HTTPS地址，并完成实际微信隐私设置和商户关联。示例AppID仅用于编译格式检查，不能代表已有微信账号。

账号页提供手机号短信验证码登录与原生微信登录。首次验证的新手机号自动创建会员；已有微信会员应先微信登录，再在“账户与安全”绑定手机号，后续短信登录仍使用原会员。若手机号或微信已属于其他独立会员，系统拒绝自动合并积分、资金和邀请归属，需联系客服核验处理。暂不支持在页面直接更换已绑定手机号。

后端`devMode=true`时额外提供明确标记的测试身份登录。仅在服务端返回`development=true`及`devCode`时展示本次开发验证码，不将其称为真实短信。手机号验证码属于当前号码与用途，页面提供重发倒计时和过期提示；校验错误可在服务端剩余次数内重试，已消费或失效的验证码会从表单清除。

“实名认证”页支持姓名与18位大陆居民身份证号码二要素一致性核验，单独取得同意后提交。页面只显示脱敏结果，姓名及证件原文不进入store或本地缓存，提交后、离开或卸载页面时清空。PENDING有刷新与显式重新提交入口，遵守服务端返回的租约/冷却倒计时，不自动重复发起计费核验。开发模拟结果明确标记，不具备真实核验效力，不包含人脸或活体识别，也不表示微信收款账户已同名核验。

提现页面提示并阻止未满足的实名条件，小程序JSAPI支付及收款要求当前会员已绑定真实微信。手机号会员可在本小程序“账户与安全”绑定当前微信，保持同一会员与订单。网页Native/H5付款不要求会员预先绑定微信；同订单首次选择的支付通道持久化，不能在终端间静默切换。最终准入仍由服务端校验；支付结果以服务端查单/回调为准。真实短信、身份核验、微信支付及转账需要服务端实际服务商配置，密钥不能放进本目录的VITE变量。

## 分层

- `pages`：商品、积分、购物袋、结算、订单及详情、账户、账户安全、实名认证、地址、推广、提现、规则等真实页面。
- `components`：页面框架、导航、商品卡、数量选择、订单行、退款弹窗及目录展示等复用组件。
- `store`：Pinia管理应用配置、当前会话和购物袋；401统一撤销会话并通知状态仓库。
- `api`：按商品、会员、账户安全、地址、交易拆分，调用`request.post()`、`request.get()`等封装方法，页面不直接调用HTTP传输。
- `utils/request.ts`：Axios实例、请求/响应拦截器及`uni.request`原生适配器，注入Bearer与幂等键、处理错误和超时，不依赖浏览器XHR。
- `utils/router.ts`：统一命名路由、鉴权跳转及登录后返回；采用uni-app原生页面栈，不将Web Vue Router强行用于小程序。
- `utils/wechat.ts`：微信隐私授权、登录code、地址导入、原生支付、商家转账确认。
- `composables/useCatalog.ts`：公开商品目录的局部加载逻辑；可选会话刷新失败不阻断商品展示。
- `composables/usePagedRecords.ts`：公开及会员列表使用服务端分页、筛选和全量统计；失败重试、会话隔离及并发缩页恢复。
- `composables/usePhoneChallenge.ts`：只在内存保留的短信挑战、重发/过期状态和原文清理。
- `types`：前后端请求与响应类型。
- `styles`：按基础、商品、交易、会员拆分的全局风格。

月度奖励在账户菜单中可达，只显示已双人复核且入账的记录。Native/H5网页订单在小程序中可查单、取消或复制原网页订单链接，不能调用原生JSAPI冒充原支付通道。

页面和业务组件各自管理局部表单，不把全部页面状态搬到另一个巨型composable。接口金额仍是人民币整数分；小程序不会把前端价格作为服务端权威值。

## 验证范围

`npm run test`有66项回归，对Axios原生适配器、匿名认证不携带已有会话、短信挑战倒计时/过期/号码隔离、敏感验证码清理、生产模拟认证拒绝、微信支付绑定门禁、原生鉴权跳转进行自动化检查。还覆盖过期会话不阻断公开商品、成功下单后补刷购物袋失败仍能进入订单页、已接受的购物袋写入不会被补刷失败覆盖，以及迟到响应、退出登录和绑定中切换身份的状态隔离。`typecheck`和微信生产构建检查全部16个页面及组件。

真实短信投递、身份服务商核验、微信登录、支付、确认收款与物流查询需要实际商户/服务商凭据和微信开发者工具或真机联调；没有将编译通过说成已通过真实身份或资金验收。

逐页按钮、路由、接口、保存位置和门禁矩阵见[小程序动作验收](../docs/mini-action-audit.md)。
