## 手机号与实名认证增量

网页、小程序新增手机号验证码登录及首次自动注册，已有微信会员可初次绑定手机号并保留原uid、邀请码和资产。占用冲突不自动合并；验证码单次消费、5分钟过期、60秒重发冷却、5次错误锁定，并有手机/IP/全局预算限制。开发验证码不能在生产兑换会话。

实名认证按姓名和身份证二要素匹配实现。格式正确不等于实名通过，真实渠道必须明确匹配；原文加密、接口脱敏、用户单独同意、失败独立计数，PENDING租约和服务端retryAfter支持有限重试。提现申请及执行双重检查，生产拒绝开发模拟结果和未绑定微信的账户。没有实现或宣称人脸活体、微信收款人同名核验。

真实浏览器用两个独立上下文并实际等待短信冷却，验证手机首次注册、退出后同号回到原会员、旧账户绑定后手机登录仍保留uid/邀请码、实名模拟结果脱敏且刷新保留，原始姓名/身份证不进入localStorage。该用例使用本地显式开发通道，未向真实手机发送短信或进行真实证件查询。

Nginx构建及实际HTTP代理验证通过：伪造的X-Forwarded-For被连接来源覆盖，Forwarded和X-Forwarded-Prefix移除。只从明确可信代理采信原始客户端IP。证据见docs/test-reports/account-proxy-boundary.txt。

## 本次结构与启动修复

后端根包仅保留Application入口，17个Controller调用Service接口；33个Mapper和30个Entity承担持久化，SQL离开Service。普通CRUD使用BaseMapper；购物袋复合主键及事务锁查询使用显式领域SQL。业务实现按订单、库存、支付、退款、分销、提现、月结、后台和初始化拆分，没有保留JdbcTemplate通用数据库入口。

网页拆成router、store、views、components、api、utils及布局/组合逻辑；领域API使用封装后的`request.post/get`，Axios集中处理令牌、幂等头和响应。小程序拆成15个原生页面，使用相同领域边界与适用于uni.request的Axios适配器。公共浏览不依赖登录状态恢复成功，下单成功不会因后台购物袋刷新失败而中断跳转。

根pom.xml可直接由IDE导入；新增Windows Maven启动器，跟踪不含密钥的网页开发默认配置，默认local服务不再要求商户参数。首次随机管理员凭据只存本地私有文件，日志只输出文件路径。prod仍强制关闭开发能力并校验真实渠道配置。

## 后端关键断言

- 同一幂等请求只生成一笔订单；同键不同内容拒绝，报价消费后不能另键重复使用。
- 未付取消恰好释放一次库存和积分；已支付超时扫描不误释放。
- 50次重复支付确认只发生一次库存扣减与赠分；错金额拒绝。
- 价格由服务端读取，报价后变价拒绝，积分不足和超过抵扣上限拒绝。
- 二级归因按父/祖父冻结，只有支付后计佣，受商品毛利和月预算约束。
- 连续三次部分退款加重复成功通知，不超过现金、积分和商品数量上限。
- 出款后发生来源退款生成追偿负债，不产生负可用余额。
- 提现不能超用余额，同一人不能审核并执行，重复到账事件不重复核销。
- 会员不能读他人订单，会员令牌不能调用财务管理权限。
- 月结不重复创建，同人复核拒绝，审批后只入账一次。
- 错误密码不会回滚限流计数；账本重建可发现人工制造的差异。
- 12个并发请求竞争5件库存，只有5次预占成功，库存与订单一致。
- RSA签名篡改、过期、错误平台序列号和AES-GCM认证失败均拒绝。
- 物流响应只暴露时间与轨迹，查无记录不展示为签收成功。
